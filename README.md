# Spread Radar

Telegram-бот для мониторинга рыночных данных. Каждые 30 секунд он опрашивает публичные API четырёх криптобирж (Binance, Bybit, OKX, Kraken), сводит котировки BTC, ETH и SOL к единому формату, отсеивает аномальные данные и показывает:

- лучшие цены покупки и продажи по биржам и межбиржевой разрыв в базисных пунктах;
- надёжность и скорость каждой биржи: доступность и задержку p50/p95;
- уведомления, когда разрыв цен превышает заданный порог.

Ключи API и аккаунты на биржах не нужны: используются только публичные рыночные данные. Бот ничего не покупает и не продаёт.

## Результаты запуска

На живых API все 4 биржи по 3 монетам ответили без ошибок и аномалий (`ok=12 outliers=0 errors=0` в каждом цикле). Один цикл из 12 запросов занимает 1,3–1,5 секунды: запросы идут параллельно, поэтому время цикла равно самому медленному ответу, а не сумме всех.

Формат ответа на `/price` (цифры условные):

```
BTC/USDT · данные 12 с назад
Биржа            Bid         Ask    мс
Binance     67000.00    67000.50    42
OKX         67010.00    67010.50    88
...
Лучший bid: OKX 67010.00
Лучший ask: Binance 67000.50
Межбиржевой разрыв: +1.4 bps (bid на OKX выше ask на Binance)
```

## Команды

| Команда | Что делает |
| --- | --- |
| `/price` | котировки по всем монетам |
| `/price BTC` | котировки по одной монете |
| `/latency` | доступность и задержка бирж за последний час |
| `/alert 5` | уведомлять, когда разрыв превысит 5 bps |
| `/alert off` | отключить уведомления |
| `/stats` | сколько данных накоплено |

1 bps (базисный пункт) = 0,01%.

## Как устроено

```
bot.py        Telegram: команды, форматирование, расписание сбора и очистки
service.py    Логика: параллельный сбор, отсев аномалий, разрыв цен, здоровье бирж, алерты
exchanges.py  Адаптеры бирж: у каждой свой символ и формат ответа, наружу — единый Quote
db.py         SQLite: снапшоты котировок и подписки
tests/        23 теста на подменённых биржах
```

Один цикл сбора:

1. 12 запросов (4 биржи × 3 монеты) отправляются параллельно.
2. Адаптер переводит символ на язык своей биржи (`BTC/USDT` → `BTCUSDT`, `BTC-USDT` или `XBTUSDT`) и замеряет время ответа.
3. Ответ проверяется: цены положительные, bid не выше ask, код ошибки внутри тела ответа равен успеху.
4. Котировки одной монеты сравниваются с медианой по биржам. Отклонение больше 1% — аномалия, она не участвует в расчётах.
5. В базу пишется всё: корректные котировки, аномалии и ошибки. По ним считается надёжность источников.
6. Если разрыв превысил порог подписчика, бот шлёт уведомление, но не чаще раза в 10 минут по одной монете.

Раз в 6 часов удаляются данные старше 7 дней.

## Решения

**Разница источников спрятана в адаптерах.** У каждой биржи свой символ (у Kraken биткоин — XBT) и своя структура ответа. Каждый адаптер — три коротких метода. Новая биржа — это один новый класс, остальной код не меняется.

**Ошибка внутри HTTP 200.** Bybit, OKX и Kraken сообщают об ошибке в теле ответа со статусом 200. Если проверять только HTTP-статус, в базу молча попадёт мусор, поэтому адаптеры проверяют `retCode`, `code` и `error`.

**Медиана, а не среднее.** Одна сломанная биржа сдвигает среднее, но не медиану. Для отсева нужно минимум три источника: при двух непонятно, какой из них ошибается. Аномалии сохраняются с пометкой, а не выбрасываются.

**p95, а не среднее время.** Среднее прячет редкие медленные ответы. p95 показывает, насколько медленными бывают худшие 5% запросов.

**Устаревшие данные не показываются.** Котировки старше трёх циклов сбора (90 секунд) не попадают на доску, чтобы цена упавшей биржи не висела как актуальная.

**Сбой одной биржи не ломает сбор.** `asyncio.gather(..., return_exceptions=True)` собирает ответы остальных, а ошибка записывается в базу и учитывается в `/latency`.

## Ограничения

- Разрыв считается без комиссий и объёмов в стакане, это мониторинг, а не торговый сигнал.
- Задержка измеряется от машины, где запущен бот, через обычный интернет, а не от сервера рядом с биржей.
- SQLite подходит для одного процесса; для нескольких сервисов нужна PostgreSQL.

## Запуск

Нужен Python 3.10 или новее и токен бота от [@BotFather](https://t.me/BotFather).

```bash
git clone https://github.com/<username>/spread-radar.git
cd spread-radar
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env               # Windows: copy .env.example .env
# впиши токен в .env
python bot.py
```

Настройки в `.env`: список монет, частота сбора, порог аномалии, пауза между алертами, срок хранения данных.

Тесты не требуют интернета:

```bash
python -m pytest -q
```

Код и тесты написаны с помощью AI coding tools. Я поставила задачу, разобрала решения, запустила бота на живом API и проверила результаты.
